# 喵汪小镇 · 猫猫还原技术架构（3D 骨骼母版 + 实时像素化）

> 目标：一套母版骨骼驱动所有猫的所有动作；每只猫只是一份数据（Pet DNA + 一张印记贴图）；画风由渲染管线统一输出为 HD-2D 像素风。
> 工作量从「动作数 x 宠物数 x 帧数」降为「动作数 + 宠物数」。

## 1. 三层解耦

| 层 | 产出 | 做几次 | 代码位置 |
| --- | --- | --- | --- |
| 外观层 | Pet DNA JSON + 印记贴图（或印记描述） | 每只宠物一次 | `prototype/public/pets/*.json` |
| 动作层 | 母版骨骼 + 动作片段 + 程序化层 | 每个动作一次，全猫通用 | `prototype/src/anim/` |
| 画风层 | 低分辨率渲染 + 卡通色阶 + 描边 + 像素对齐 | 全局一次 | `prototype/src/render/` |

硬性约束（违反任何一条就回到了旧路线）：

1. 动作片段文件里**不允许**出现任何宠物 id、宠物颜色或宠物专属贴图引用。
2. 宠物目录里**只允许**出现 JSON 和图片，不允许出现动作数据或代码。
3. 印记只存在于模型表面的贴图上，不存在于任何一帧画面里。

## 2. 母版猫（Base Rig #2）

### 2.1 来源

- 验证阶段：`prototype/src/cat/` 下的程序化构建器直接生成蒙皮网格（参数化部件 -> 网格 + 骨骼权重 + 形态键 + 非镜像 UV）。
  对外接口是 `CatAsset { mesh, skeleton, bones, partLayout }`，和 Blender 导出的 GLB 等价。
- 量产阶段：demo 内「导出 GLB」得到 `cat_base.glb`，导入 Blender 精修造型和动作后再导出 GLB 替换即可，运行时代码不需要改。

### 2.2 比例（Q 版）

单位：1 = 1 米级抽象单位，地面 y = 0，猫朝 +Z，猫自身的左侧为 +X。

| 部件 | 中心 | 尺寸 |
| --- | --- | --- |
| 身体 | (0, 0.52, 0) | 椭球半径 (0.29, 0.27, 0.48) |
| 头 | (0, 0.92, 0.55) | 椭球半径 (0.36, 0.32, 0.31)，头身比约 1:1.4 |
| 嘴套 | (0, 0.83, 0.80) | 椭球半径 (0.14, 0.085, 0.08) |
| 腿 | 肩/胯高 0.45 | 短腿，爪球半径 0.075 |
| 尾巴 | 根部 (0, 0.6, -0.5) | 6 节骨骼，向后上方弯曲 |

### 2.3 骨骼

```
root（位移/朝向，供闲逛移动）
└─ hips
   ├─ spine ─ chest ─ neck ─ head ─ earL / earR
   │          ├─ shoulderL ─ elbowL ─ fpawL
   │          └─ shoulderR ─ elbowR ─ fpawR
   ├─ hipL ─ kneeL ─ hpawL
   ├─ hipR ─ kneeR ─ hpawR
   └─ tail0 ─ tail1 ─ tail2 ─ tail3 ─ tail4 ─ tail5
```

所有骨骼静止姿态的局部轴与世界轴对齐，动作数据直接写欧拉角（度）：

- 绕 X 正方向：低头 / 腿向后摆。
- 绕 Y 正方向：向猫自身左侧转。
- 绕 Z 正方向：向猫自身右侧歪（歪头）。

### 2.4 UV 与贴图像素密度规范

- **UV 绝不左右镜像**：左右耳、左右脸、四条腿各有独立区域。非对称五印记依赖这一点。
- 印记贴图 256x256，最近邻采样，不开 mipmap。
- 贴图像素密度约 56 像素/单位；默认镜头下屏幕约 60-70 像素/单位，即一个贴图像素约等于一个屏幕像素，不会出现糊边中间色。
- 图集布局（像素）：

| 区域 | 矩形 (x, y, w, h) | 映射 |
| --- | --- | --- |
| 头 | 0, 0, 128, 64 | 横向绕 Y 一圈（中线 = 正脸），纵向从头顶到下巴 |
| 嘴套 | 128, 0, 64, 32 | 同上 |
| 身体 | 0, 64, 128, 96 | 横向绕身体一圈（中线 = 背），纵向从尾到胸 |
| 四条腿 | 128, 32 起，每条 32x48 | 横向绕腿一圈，纵向从肩到爪 |
| 左右耳 | 128, 80 / 160, 80，各 32x32 | 横向绕耳一圈，纵向从耳根到耳尖 |
| 尾巴 | 0, 160, 128, 32 | 横向从尾根到尾尖，纵向绕尾一圈 |

### 2.5 形态键（体型）

形态键只改外形、不移动骨骼，所以不会破坏任何动作。

| 键 | 0 | 1 |
| --- | --- | --- |
| `headRound` | 标准头 | 更宽更圆的大饼脸 |
| `weight` | 标准身材 | 圆滚滚、肚子下垂 |
| `earSize` | 标准耳 | 大耳朵 |
| `tailFluff` | 细尾 | 蓬松大尾巴 |
| `cheekFluff` | 无腮毛 | 腮毛外扩 |
| `muzzleSize` | 小嘴套 | 饱满嘴套 |

腿长会移动关节位置，验证阶段不做形态键（Q 版统一短腿）；量产需要时改为调整骨骼长度。

## 3. Pet DNA 规范

```json
{
  "id": "mimi",
  "name": "咪咪",
  "shape": { "headRound": 0.6, "weight": 0.35, "earSize": 0.5, "tailFluff": 0.6, "cheekFluff": 0.5, "muzzleSize": 0.7 },
  "coat": {
    "texture": null,
    "base": "#8a6a4f",
    "palette": ["#8a6a4f", "#5b4332", "#f4efe6", "#c98a3e", "#b89474"],
    "markings": [
      { "type": "stripes", "color": "#5b4332", "axis": "z", "frequency": 9, "width": 0.35, "region": { "minY": 0.55 } },
      { "type": "blob", "color": "#c98a3e", "center": [-0.07, 0.84, 0.86], "radius": [0.1, 0.08, 0.1], "noise": 0.25 }
    ]
  },
  "eyes": { "iris": "#c9a43a", "pupil": "#1b1410" },
  "nose": "#d98c8c",
  "personality": { "idle": 0.3, "walk": 0.3, "sit": 0.15, "loaf": 0.15, "groom": 0.1 }
}
```

- `coat.texture` 不为空时直接用画好的 PNG（美术在 Blender 或 demo 的「绘制印记」模式里画出来导出）。
- `coat.texture` 为空时，用 `markings` 在母版静止姿态的 3D 空间里描述印记，加载时**烘焙**到非镜像 UV 贴图。印记可以跨越部件边界（比如从嘴套连到鼻梁），不用关心 UV 接缝。
- 印记类型：
  - `blob`：椭球色块，`center`/`radius` 为模型空间坐标，`noise` 为边缘不规则度，可选 `minX`/`maxX` 等裁切。
  - `underside`：腹部/下巴/胸口浅色，按法线朝下程度和高度判定。
  - `stripes`：狸花条纹，沿某轴的正弦条纹，可限定区域。
  - `part`：整个部件染色（如四只白手套 `fpawL`）。
- 左右一律指**猫自身的左右**（猫左 = +X）。主人从正面看照片时的「右边」是猫的左边，录入时要换算。
- `palette`：烘焙后把每个像素吸附到调色板最近色，保证贴图是干净的像素画，不出现过渡色。

## 4. 动作层

### 4.1 动作片段

- 每个动作一个文件：`prototype/src/anim/clips/<name>.ts`，用关键帧 DSL 描述骨骼欧拉角、`hips` 位移、以及表情轨（眼睛/嘴的贴图状态）。
- 注册在 `prototype/src/anim/clips/index.ts`。**新增动作 = 新增一个文件 + 注册一行**，不碰任何宠物资源。
- 未写到的骨骼自动补静止姿态，保证动作间交叉淡入淡出干净。

首批动作：

| 动作 | 名称 | 循环 | 说明 |
| --- | --- | --- | --- |
| `idle` | 待机呼吸 | 是 | 胸腔起伏、微点头 |
| `walk` | 走 | 是 | 对角步态，移动速度与步频匹配 |
| `sit` | 坐下 | 是 | 后腿折叠、前腿撑地 |
| `loaf` | 揣手手 | 是 | 四肢收进身体下方、眯眼 |
| `groom` | 舔毛 | 是 | 坐姿抬右前爪，舔爪 + 吐舌表情 |
| `stretch` | 伸懒腰 | 否 | 第 6 个动作，用于验证门槛 2 |

### 4.2 程序化层（运行时叠加，零美术成本）

每帧顺序：还原上一帧的动画姿态（去掉上一帧的程序化叠加）-> 动画混合器写入动作 -> 记下动画姿态 -> 程序化层叠加。
注意：three.js 的动画混合器只在数值变化时才写骨骼，所以不能每帧复位到静止姿态，否则「坐着不动」这类恒定姿态会被抹掉。

- 看向：头和脖子按权重转向鼠标/玩家，限制角度。
- 尾巴弹簧：每节尾骨是一个阻尼弹簧，受身体转向、移动速度和慢速噪声驱动，尾尖滞后于尾根。
- 呼吸：胸腔微幅起伏叠加在任何动作上。
- 耳朵抖动：随机间隔的单耳快速抖动。
- 眨眼：随机间隔切换眼睛贴图；动作的表情轨优先。
- 脚部 IK：小镇地面目前是平地，暂不启用；有坡地后再加。

### 4.3 闲逛状态机（性格 = 权重）

`idle -> 按 personality 权重挑下一个状态 -> walk 到随机点 / sit / loaf / groom -> ...`
同一套动作库，不同权重就是不同性格：懒猫 `loaf` 权重高，好动的猫 `walk` 权重高。

## 5. 画风层（像素化渲染管线）

1. 场景渲染到低分辨率目标（默认屏幕尺寸 / 像素倍率，倍率 3），最近邻采样。
2. 卡通材质：3 档色阶渐变贴图，主光 + 环境光 + 阴影。
3. 描边：后处理读深度，物体边缘一像素描边，颜色取自身颜色压暗（不是纯黑），更柔和。
4. 可选调色板量化：每通道限定色阶，强化像素画质感。
5. 像素对齐相机：正交相机，跟随目标时把相机位置吸附到像素网格，避免移动时画面闪烁。
6. 脸部：眼睛和嘴是手绘像素贴图集（睁眼/眨眼/开心眯眼/困/惊讶；闭嘴/张嘴/吐舌），贴在头骨上的小面片，切换状态而不是网格形变。

## 6. 验证门槛

| 门槛 | 判定方式 |
| --- | --- |
| 1. 主人 3 秒认出自家猫 | 人工：主人看 demo 截图/实机 |
| 2. 新增第 6 个动作不碰宠物专属资源 | 自动：`npm run check` 检查动作文件不引用宠物；`stretch` 是后加的动作，所有宠物直接可用 |
| 3. 换猫只需贴图 + DNA | 自动：`npm run check` 检查宠物目录只有 JSON/图片；demo 内切换三只猫，动作完全共用 |

## 7. 工具链

- 建模/绑定/动作精修：Blender + Rigify（免费）。
- 运行时：three.js + TypeScript + Vite。
- 像素贴图：LibreSprite（免费）或 Aseprite；也可直接用 demo 的「绘制印记」模式。
- 资源格式：glTF/GLB。

## 8. 运行

需要 Node 18+（本机用 `~/.nvm/versions/node/v20.20.2`）。

```bash
cd 喵汪小镇/prototype
npm install
npm run dev      # 打开 http://localhost:5173
npm run check    # 门槛 2、3 自动检查
npm run build    # 类型检查 + 生产构建
```

URL 参数（方便截图对比）：`pet=mimi|juzi|nainiu`、`action=idle|walk|sit|loaf|groom|stretch`（定住该动作）、
`scale=1..6`（像素倍率）、`zoom`（视野高度，越小越近）、`heading`（猫朝向，弧度）、`pitch`（镜头俯角）、`ui=0`（隐藏面板）。

交互：鼠标移动猫会看你；点猫会歪头、眯眼开心；「在猫身上绘制」模式下直接在 3D 猫身上画印记，画完「导出印记 PNG」，
放进 `public/pets/` 并在 DNA 里填 `coat.texture` 即可。

## 9. 验证结果（2026-10-27）

| 门槛 | 结果 |
| --- | --- |
| 1. 主人 3 秒认出 | **待主人判定**。截图见 `docs/validation/`。咪咪的五印记全部按非对称规范落在模型表面：右嘴套焦糖块连鼻、左嘴套鼻下纯白、唇下窄浅棕、左腹通背白云斑；6 个动作里印记位置始终正确。底色（棕狸花 + 白腹）是按旧记录推测的，需主人确认 |
| 2. 新增动作不碰专属资源 | **通过**。`stretch`（伸懒腰）是后加的第 6 个动作，只新增 `clips/stretch.ts` + 注册一行，三只猫直接可用；`npm run check` 通过 |
| 3. 换猫只需贴图 + DNA | **通过**。咪咪 / 橘座 / 奶牛 三只猫只有三份 JSON 的差异（体型、印记、眼睛、性格），共用同一网格、骨骼、6 个动作；用 PNG 贴图加载（`mimi_coat.png`）与用 markings 烘焙结果逐字节一致 |

其他已验证项：

- 母版 GLB 导出 -> 重新加载：26 根骨骼、6 个形态键、6 个动作完整（`assets/cat_base.glb`）。
- 像素对齐：镜头只按整像素移动（例：像素世界尺寸 0.0081 时相机位置为 0.0163 / 0.0244 / 0.0407…），剩余亚像素偏移放到最终放大采样里，始终在 ±0.5 像素内。
- 闲逛状态机：模拟 3 分钟，6 个状态都会出现，走路始终在可走区域内。

已知不足 / 下一步：

- 母版造型目前由代码生成（本机没有 Blender），比例和关节已可用，但腿和爪偏「圆柱」。下一步把 `assets/cat_base.glb` 导入 Blender 精修造型和动作，再导出替换。
- 唇下窄浅棕这类很细的印记在默认镜头下只有 1-2 个像素，近景才看得清。要不要放大嘴套区域的贴图像素密度，取决于主人判定的结果。
- 坐姿时尾巴偶尔穿地，后续有坡地/家具时需要加脚部 IK 和尾巴碰撞。
